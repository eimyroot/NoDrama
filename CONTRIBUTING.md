# Contributing

Thanks for contributing to NoDrama.

## Before you start

- Open an issue for substantial product, billing, privacy, or architecture changes.
- Keep changes narrowly scoped and avoid unrelated refactors.
- Never commit credentials, secrets, production data, private messages, or personal data.
- Preserve explicit user review for generated communication unless a reviewed product decision says otherwise.

## Development

Use the environment and commands documented in the repository. Install dependencies from the lockfile, run the available checks, and verify affected flows locally before opening a pull request.

## Pull requests

Explain what changed, why it changed, how it was tested, and any compatibility, privacy, billing, or security impact. Keep generated files and unrelated formatting churn out of the diff.

By contributing, you agree that your contribution is submitted under the repository's existing proprietary license and project terms unless a separate written agreement applies.
